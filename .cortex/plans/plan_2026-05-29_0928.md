## Fix: replication `_pct` runaway ($258M) — standardize on whole-number percents

### Context / root cause
`calcReplicationForYear()` in the proposal template consumes `replication.storage_growth_pct` / `yoy_pct` **raw** with fractional defaults (`0.15`/`0.10`) and a slider that does `×100`/`÷100`. Every other `_pct` in the spec (`storage.annual_growth_pct`, `scenarios.growth_pct`) is a **whole-number percent** divided by 100 at use. The M&S fixture authored `25`/`20` (whole-number convention), so the replication code read them as 2500%/2000% growth, compounding to a Year-3 replicated footprint of ~788,000 TB and ~$217.6M storage alone → grand TCV $258.1M vs core $1.97M.

Decision (confirmed): standardize replication on **whole-number percents** to match the rest of the spec.

Other fixtures (`acme`, `enterprise-gcp`, `healthcare`, `light-and-wonder`) hold fractional values (`0.15`/`0.2`/`0.1`/`0.05`) but are `replication.enabled: false`, so they render fine today yet carry wrong-convention values. M&S is the only enabled one and is already correct under the new convention.

### Implementation steps
1. **`assets/templates/proposal-template.html`** — convert replication to whole-number percents:
   - L1211–1212 (`calcReplicationForYear`): `yoy = (rep.yoy_pct != null ? rep.yoy_pct : 10) / 100;` and `growth = (rep.storage_growth_pct != null ? rep.storage_growth_pct : 15) / 100;`
   - L2453–2454 (enable-seed defaults): `storage_growth_pct ?? 15`, `yoy_pct ?? 10`
   - L2539–2540 (slider): `value="${Math.round(rep.storage_growth_pct ?? 15)}"`, `onchange="updateReplication('storage_growth_pct', +this.value)"` (drop ×100/÷100)
   - L2543–2544 (slider): same for `yoy_pct` (`?? 10`, drop ×100/÷100)

2. **Normalize the 4 disabled fixtures** to whole-number percents (correctness + prevent future foot-gun if enabled):
   - `acme-financial-3year-sizing.json`: 0.15→15, 0.1→10
   - `enterprise-gcp-fullstack-3year.json`: 0.2→20, 0.1→10
   - `healthcare-bc-slowramp-3year.json`: 0.1→10, 0.05→5
   - `light-and-wonder-3year-sizing-v1-2026-05-26.json`: 0.15→15, 0.1→10
   - **M&S fixture: no change** (25/20 already correct).

3. **`framework/sizing_spec_schema.json`** — document + bound the fields: add `"description": "Whole-number annual percent, e.g. 25 = 25%."` and `"maximum": 100` to `replication.storage_growth_pct` and `replication.yoy_pct` (defense-in-depth against absurd inputs the guard can then reject).

4. **`scripts/html-render-check.py`** — add a JS≫Python divergence guard so this class of silent blowup fails loudly: WARN when `JS_TCV > Python_TCV × 3`, FAIL when `> × 10` (legit excluded-cost overhead observed at 1.1–1.8x; M&S was 131x). Keep the existing JS<Python check.
